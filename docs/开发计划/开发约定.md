# 开发约定

> 版本：v1.0  
> 日期：2026-11-17  
> 依据：`最终开发计划决定.md`、`CLAUDE.md`、`docs/requirements/`（已冻结）、`原型图/`  
> 说明：本文件只约定开发顺序、前端提示词和交付习惯；详细任务与实现口径以 `最终开发计划决定.md` 为准。

---

## 1. 总原则

- 需求已冻结，不再修改 `docs/requirements/` 和 `原型图/`；不自行新增业务规则。
- 采用**纵切开发**：每个功能同时完成后端、前端、联调、测试、文档，不做“前端全量先行 + 最后联调”。
- 视觉统一使用**白橙主题**（D1）。
- **不新增数据库字段**（D3）；阶段“已截止不得延长”通过保存时校验实现。
- 接口契约以 `docs/design/api.md` 为准；页面不自己发明字段和错误码。
- 上线前必须通过 `mvn test`、`npm run lint`、`npm run build`。

---

## 2. 开发顺序

```text
P0 前端基座：脚手架、白橙主题、布局、公共组件、request.js
  ↓
P1 登录页
  ↓
P2 主页面 / 公告页 / 个人待办 / 阶段管理页
  ↓
P3 查看实训室信息 / 提交实训室信息
  ↓
P4 志愿填报 / 分轮补录
  ↓
P5 发放拟录取
  ↓
P6 拟录取确认
  ↓
P7 调剂结果只读
  ↓
P8 全链路回归、加固、上线
```

规则：

- 前端可以先行，但**最多比后端领先一个纵切**。
- 不一次性铺完所有页面；每完成一个页面/纵切就联调一次。
- 后端接口未实现时，用 `VITE_USE_MOCK=true` 的独立 mock 层；正式页面不写死演示数据。

## 3. 前端提示词规范

### 3.1 一次给一个页面或一个纵切

不要一次给 10 个页面的提示词。一次给一个页面，最多一个纵切；多个页面我会按 P0 → P1 → P2 … 的顺序拆开做。

### 3.2 提示词必须包含

| 项 | 说明 |
| --- | --- |
| 页面与路由 | 如“登录页 `/login`” |
| 角色 | 公开 / 学生 / 导师 / 负责人 |
| 对应原型 | 如 `原型图/登录.html` |
| 使用接口 | 如 `POST /auth/login`、`GET /auth/me` |
| 页面状态 | 加载中 / 空 / 失败分别怎么显示 |
| 表单逻辑 | 初始禁用、满足什么条件启用、提交中禁用、失败是否保留内容 |
| 关键文案 | 与需求一致的错误提示、成功提示 |
| 验收要点 | 需要手工验证哪些状态和流程 |
| 特殊限制 | 如“不提供搜索/候选”“不做角色切换” |

### 3.3 提示词模板

```text
页面：登录页 /login
角色：公开
原型：原型图/登录.html
接口：POST /auth/login、GET /auth/me

要求：
- 角色三选一，未选角色时登录按钮禁用；
- 学工号只校验 ^\d{10}$；
- 点击“人脸比对”只做前端模拟，成功后显示“比对成功”并锁定输入框；
- 比对成功且已选角色后，登录按钮启用；
- 错误文案“学工号异常”；
- 登录成功按角色进入 /home；
- 不做注册、密码、真实人脸识别。

验收：
- 三个角色都能登录；
- 空值/非 10 位/含非数字提示“学工号异常”；
- 未比对不能登录；比对后学工号不可改。
```

## 4. 前端实现约定

> 前后端目录与模块落位详见 `代码目录约定.md`。

- 全部使用 Vue 3 **Composition API + `<script setup>`**，不用 Options API。
- 组件不直接调用 Axios；请求统一封装在 `src/api/*.js`，命名 `getXxx / createXxx / updateXxx / confirmXxx`。
- `src/api/request.js` 统一处理：
  - `baseURL: '/api/v1'`
  - `withCredentials: true`
  - `code !== 200` 弹 Toast
  - HTTP 401 清用户状态并跳登录
  - HTTP 403 提示“无权访问该数据”
  - 网络异常提示“网络异常，请重试”
- 每个页面必须处理**加载中 / 空状态 / 加载失败**三态；加载失败不能显示成“暂无数据”。
- 表单统一：初始禁用 → 条件满足启用 → 提交中禁用防重复 → 失败保留已填内容。
- 主题使用白橙变量，不在模板里散落新的硬编码色值；不引入 Element Plus / Ant Design Vue / Naive UI。
- 图标使用内联 SVG；字体自托管 `Noto Sans SC` + `Rajdhani`，不直连 Google Fonts。
- 页面复用 `DefaultLayout`、`AppSidebar`、`AppHeader`，不复制布局。
- 不用 `localStorage` 里的角色/学工号做鉴权；以服务端 Session 为准。
- 提交前移除 `console.log`、`debugger`；正式页面不硬编码演示数据。
- 倒计时以服务端 `serverTime` 为准，前端计算偏移，不只依赖浏览器时钟。

## 5. 后端与联调约定

- Controller 只收参、`@Valid` 校验、调用 Service、返回 `Result`；业务规则写在 Service。
- 所有写操作在 Service 层用 `@Transactional`；名额、确认、发放必须锁行 + 唯一索引兜底。
- 任何个人数据查询必须带当前用户条件；URL/请求体里的资源 ID 先查归属再操作。
- Controller 不返回实体，统一返回 DTO。
- 时间通过可注入的 `Clock` 获取；所有开放/截止判断以服务端时间为准。
- 错误码按 `CLAUDE.md`：40101、40301、40401、40901、50001、50002。
- 每个纵切顺序：后端接口 → Service 规则/事务 → 后端测试 → 前端页面 → 真实联调 → 手工验收 → 文档同步 → 合并。
- 联调必须使用真实后端；mock 只用于后端未实现前的临时前端开发。

## 6. 交付与验收

### 6.1 单个页面

- [ ] 加载中 / 空 / 失败三态正确。
- [ ] 表单禁用/启用、提交中禁用、失败保留内容正确。
- [ ] Toast 文案与需求一致。
- [ ] 角色菜单、路由守卫、直接访问 URL 正确。
- [ ] 复用公共布局和组件，视觉与白橙原型一致。
- [ ] 无 `console.log`、`debugger`、硬编码演示数据。
- [ ] `npm run lint`、`npm run build` 通过。

### 6.2 单个纵切

- [ ] 后端接口、事务、权限、归属校验完成。
- [ ] 后端关键规则有测试；`mvn test` 通过。
- [ ] 前端页面接真实接口联调通过。
- [ ] 手工验收覆盖正常、空、失败、越权、重复提交。
- [ ] 接口/表结构变更同步 `docs/design/`。
- [ ] 没有硬编码身份、密码、绝对路径。
- [ ] 提交信息使用 Conventional Commits。

## 7. 已定实现口径

| 事项 | 约定 |
| --- | --- |
| 主题 | 白橙；同步修正 `CLAUDE.md` §6.2 的深色变量 |
| 阶段延长 | 不新增字段；已截止阶段的 `end_at` 不得改到未来，否则提示“阶段已截止，不能延长” |
| 名额 | 三轮累计；占用 = 最终录取 + 未过期待确认 offer |
| 轮内子步骤 | 不新增子阶段配置；主页面只显示“第 N 轮录取”，待办按用户状态推导 |
| 公告 | 前端生成草稿可编辑；后端校验保存；`stage_change` 存草稿供失败重试 |
| 文档 | 统一迁移到 `docs/design/api.md`、`db-schema.md`、`architecture.md` |
| 接口命名 | 保留 `GET /teacher/admissions`；同步修正 CLAUDE.md 示例 |
| 调剂 | 线下确定，线上只读；脚本/初始化导入，不做线上确认 |
| 分数 | 0–100，`DECIMAL(5,2)` |
| 负责人 | 不可查看学生录取明细 |
| 测试数据 | 仅 dev 的 `data.sql` + reset 脚本 |

## 8. 禁止事项

- 不做注册、密码登录、找回密码。
- 不做真实人脸识别，不采集/存储人脸数据。
- 不做公告新增/编辑/删除。
- 不做线上调剂确认/导师接收。
- 不做短信、邮件、站内推送。
- 不做第四轮填报。
- 不做角色切换和原型演示开关。
- 不把 `uploads/` 映射为静态资源。
- 不用 `localStorage` 角色/学工号做鉴权。
- 不把“加载失败”显示成“暂无数据/暂无待办”。
- 不只在菜单/路由隐藏入口而不做后端校验。
- 不在 SQL 中使用 `${}` 拼接。
- 不让 Controller 直接返回实体。
- 不把名额/确认只靠前端置灰防重复。
