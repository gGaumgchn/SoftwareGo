# 软件学院实训室选拔系统 · 页面原型图设计

## 一、概述

本原型依据 `requirements` 目录下的需求文档设计，覆盖软件学院实训室选拔系统的全部页面，角色分为 **学生、导师、负责人** 三类。

- 设计基调：**白橙主调、科技、简约**，避免花哨装饰，突出信息层级与操作效率。
- 运行环境：Web 端，按 **1920 × 1080** 分辨率设计（侧边栏 238px + 内容区自适应）。
- 交付形式：每个页面一个独立 HTML 文件，页间通过链接跳转，可直接双击打开浏览。

## 二、设计规范

### 2.1 配色

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 页面背景 | `#f5f6fa` → `#ffffff` | 白浅灰渐变底，配淡橙径向光晕与网格纹理 |
| 面板背景 | `#ffffff` / `#f6f7fb` | 卡片、侧边栏、顶栏 |
| 主强调色 | `#ff7a18`（橙） | 选中态、主按钮、倒计时、当前阶段 |
| 辅助强调色 | `#ff9a45`（浅橙） | 次级强调、边框高亮 |
| 正文 / 次要 / 弱化文字 | `#1f2937` / `#64748b` / `#94a3b8` | 三级文字层级 |
| 状态色 | 绿 `#34d399`、琥珀 `#fbbf24`、红 `#f87171` | 已确认 / 待确认 / 已放弃、异常 |

### 2.2 字体

- 中文正文与标题：`Noto Sans SC`（400 / 500 / 700）。
- 数字、倒计时、英文标识：`Rajdhani`（科技感等宽数字）。
- 通过自托管镜像加载，不直连 Google Fonts。

### 2.3 布局

```
┌─────────┬──────────────────────────────────┐
│         │  顶栏（页面标题 + 用户信息）        │
│ 侧边栏   ├──────────────────────────────────┤
│ 品牌标识 │                                  │
│ 功能菜单 │        内容区（卡片式）            │
│         │                                  │
└─────────┴──────────────────────────────────┘
```

- 左侧边栏：品牌标识 + 角色功能菜单 + 退出登录入口。
- 顶部栏：当前页面标题 + 用户姓名 / 学工号 / 角色标签。
- 内容区：以「卡片」承载各功能区，标题用橙色圆点标识。

### 2.4 组件

按钮（主 / 次 / 幽灵）、输入框、单选组、文件上传区、卡片、表格、状态徽标、步骤条、倒计时、弹窗、全局 Toast、空状态。

### 2.5 交互原则

- 所有表单均实现「初始禁用 → 满足条件后启用 → 提交中禁用防重复提交」的闭环。
- 校验提示与需求文档一致：如「学工号异常」「导师姓名不能重复」「请上传 PDF 格式的简历」等。
- 身份通过 URL 查询参数 `?role=` 在页面间稳定传递（`localStorage` 兜底），登录后角色固定、不提供角色切换。

## 四、页面设计说明

### 4.1 登录（登录.html）

- 居中登录卡片，左侧品牌标识「实训室选拔系统」，背景为淡橙网格 + 光晕。
- **角色选取栏**：学生 / 导师 / 负责人三个单选卡片，登录前必选其一。
- 学工号输入框：10 位数字（四位年份 + 三位代码 + 三位序号），格式校验 `^\d{10}$`。
- **人脸比对**为模拟操作：格式正确即「比对成功」，锁定学工号输入框；不正确提示「学工号异常」。
- 「进入系统」按钮初始禁用，仅当 **已选身份 + 比对成功** 时启用。
- 底部说明：无需注册密码、身份以所选为准、不采集人脸数据。

### 4.2 主页面（主页面.html）

- 顶部栏展示当前身份用户信息；登录后角色固定，侧边菜单、用户信息、待办随登录身份渲染，不提供角色切换。
- 上半部分：
  - **选拔进度步骤条**：集中宣讲 → 实训室开放日 → 第一轮录取 → 第二轮录取 → 第三轮录取 → 调剂 → 正式入组；当前阶段高亮。
  - 当前阶段、起止时间、**截止倒计时**（动态秒级刷新）。
- 下半部分（左右两栏）：
  - 左：公告摘要列表，可点击查看详情。
  - 右：个人待办摘要，展示当前可办理事项与截止时间，点击前往办理。
- 学生端提供「预览已录取状态」开关：开启后展示「已录取」横幅、最终实训室与导师，待办变为「暂无待办」。

### 4.3 志愿填报（志愿填报.html）

- 提供「第一轮志愿填报 / 第二轮补录填报」模式切换，复用同一页面实现分轮补录。
- 补录模式下，顶部只读展示**仍有剩余名额的导师**（导师姓名、所属实训室、剩余名额），不出现搜索或候选选择。
- 三个**导师姓名输入框**均标注「可选」，平行志愿、不区分优先级；重复填写提示「导师姓名不能重复」。
- 两项调剂意愿（实训室内 / 学院内）分别单选「同意 / 不同意」。
- PDF 简历上传：仅支持 PDF，可替换；非 PDF 提示错误。
- 提交按钮在「至少一名导师 + 无重复 + 两项意愿已选 + 简历已上传」后才启用；提交成功弹 Toast。

### 4.4 拟录取确认（拟录取确认.html）

- 三种状态切换：**志愿拟录取 / 调剂结果（只读）/ 暂无拟录取**。
- 拟录取卡片展示：实训室、导师、轮次、确认截止时间、当前状态（待确认 / 已确认 / 已放弃）。
- 点击「确认」弹出二次确认：「确认后不可更改，其他拟录取将自动放弃」。
- 确认后：所选变为「已确认」，其余自动「已放弃」，按钮全部失效。
- 调剂结果仅展示最终去向，无确认按钮；暂无拟录取展示空状态。

### 4.5 查看实训室信息（查看实训室信息.html）

- 实训室卡片网格，展示名称、导师、研究方向、位置、计划招收人数。
- 支持按关键字（名称 / 导师 / 研究方向）与研究方向下拉筛选。
- 点击卡片弹出详情：位置、导师、计划人数、联系方式、研究方向、简介，并提供「查看导师简历（PDF）」入口。

### 4.6 提交实训室信息（提交实训室信息.html）

- 表单字段：实训室名称、位置、计划招收人数、导师姓名、研究方向、联系方式、导师简历（PDF），均为必填。
- 计划招收人数须为正整数，并校验**不得小于当前已占用名额**（演示为 2 人）。
- 展示「已提交 · 可修改」状态与最近更新时间；修改后重新提交更新原记录。
- 全部有效 + PDF 上传成功后才可提交。

### 4.7 发放拟录取（发放拟录取.html）

- 顶部名额概览：本轮招生名额 / 已确认 / 待确认 / 剩余可发放。
- 申请列表：学工号、姓名、面试分数（可录入）、状态、简历查看。
- 支持「按分数排序」、设置「录取分数线」。
- 点击「发放拟录取」：按分数从高到低，向分数 ≥ 分数线且未录取的学生发放，直至名额占满；同分学生提示需确定先后顺序。
- 名额已满、无达标学生、分数线无效时给出对应提示。

### 4.8 阶段管理（阶段管理.html）

- 阶段名称与顺序固定，仅配置起止时间（精确到分钟）；三轮录取展开为第一、二、三轮分别配置。
- 每行含阶段名称（固定）、开始时间、结束时间（`datetime-local`）。
- 「本次调整发布公告」开关：开启后自动生成公告标题与正文（可编辑），保存时随阶段一并发布。
- 校验规则：时间完整、结束晚于开始、按流程顺序且不重叠；冲突行标红并提示。
- 保存成功提示「保存成功」或「保存成功，公告已发布」。

### 4.9 公告（公告.html）

- 只读列表，展示标题、摘要、发布时间；点击查看完整正文。
- 明确标识「只读 · 发布后不可修改或删除」，无任何新增 / 编辑 / 删除入口。

### 4.10 个人待办（个人待办.html）

- 按角色展示待办列表：事项、所属阶段、截止时间、状态徽标、前往办理按钮。
- 提供「预览暂无待办」开关，展示空状态。
- 学生 / 导师 / 负责人待办内容各不相同。

## 五、页面跳转关系

```
登录.html ──(选择身份 + 比对成功)──► 主页面.html?role=<student|teacher|manager>
主页面.html ──菜单跳转──► 公告 / 个人待办 / 各角色功能页（均携带 ?role= 参数）
```

- 登录后跳转 `主页面.html?role=<student|teacher|manager>`，身份随 URL 参数传递并在后续跳转中保持。
- 主页面、公告、个人待办按 URL 的 `?role=` 参数（缺失时回退 `localStorage`，再回退「学生」）渲染对应侧边菜单与用户信息。
- 学生功能页、导师功能页、负责人功能页为固定角色页面，页内所有跳转统一追加各自 `?role=` 保持身份。
- 所有页面侧边栏底部提供「退出并重新登录」返回登录页。

## 六、使用说明

1. 直接双击 `登录.html` 进入（其余页面也可单独打开，缺省按「学生」身份渲染；可在 URL 追加 `?role=teacher` / `?role=manager` 指定角色）。
2. 登录页选择任一身份 → 输入 10 位数字学工号 → 点击「人脸比对」→ 点击「进入系统」。
   - 任意 10 位数字均符合格式（如 `2026001001`、`2026012001`、`2026017001`），不校验账号是否存在。
3. 登录后角色固定，跨页面跳转自动携带 `?role=` 参数，不会发生角色跳变。
4. 页面内数据均为**示例演示数据**（阶段时间、导师、实训室、申请学生等），与需求文档中的交互规则保持一致，不代表真实后端数据。
